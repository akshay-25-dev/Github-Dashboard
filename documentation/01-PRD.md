## 1. Overview

The GitHub Developer Dashboard is a web application that lets anyone enter a public GitHub username and instantly view a rich, visual summary of that developer's activity, skills, and achievements. It turns raw GitHub data into a shareable, portfolio-style snapshot — useful for developers checking their own stats, recruiters scanning a candidate, or anyone curious about an open-source contributor.

## 2. Problem Statement

GitHub's native profile page is functional but static and shallow. It doesn't easily answer questions like:
- What languages does this person actually work in most?
- How consistent is their contribution activity?
- Which of their repos best represent their skill level?
- What would a hiring manager take away from this profile in 10 seconds?

Developers currently stitch together third-party badges, README hacks, or manual portfolio updates to answer these questions. There's no single place that aggregates this into a clean, digestible view — with an AI-written narrative on top.

## 3. Goals & Objectives

| Goal | Description |
|---|---|
| G1 | Let any user pull up a GitHub profile's activity in under 5 seconds |
| G2 | Visualize contribution patterns (heatmap, streaks) clearly |
| G3 | Surface language and repository insights without manual digging |
| G4 | Generate a natural-language "portfolio summary" via AI |
| G5 | Produce a portfolio-quality project demonstrating REST API integration, auth, charting, and AI usage — for resume/interview purposes |

## 4. Target Users

- **Developers** who want a shareable snapshot of their own GitHub activity for a resume or LinkedIn.
- **Recruiters / hiring managers** doing a quick technical screen of a candidate's public work.
- **Open source maintainers / contributors** curious about their own or others' contribution patterns.

## 5. Core Features

### 5.1 Username Search
- Text input to enter any public GitHub username.
- Debounced validation + "user not found" handling.
- Recent searches (stored locally) for quick re-access.

### 5.2 Contribution Heatmap
- 12-month calendar heatmap (GitHub-style) showing daily commit/contribution intensity.
- Hover tooltip with exact contribution count per day.
- Total contributions in the last year.

### 5.3 Most-Used Languages
- Aggregated language breakdown across the user's repositories (by bytes of code, not repo count).
- Donut/bar chart with percentage per language.
- Top 5 languages highlighted; "other" bucket for the rest.

### 5.4 Repository Insights
- List of top repositories, ranked by stars/forks/recent activity.
- Per-repo: name, description, primary language, stars, forks, last updated.
- Filter/sort by stars, forks, or recently updated.

### 5.5 Streaks & Achievements
- Current contribution streak (consecutive active days).
- Longest streak on record.
- Achievement badges (rule-based), e.g.:
  - "Century Club" — 100+ contributions in a year
  - "Polyglot" — 5+ languages used
  - "Early Bird" — account older than 5 years
  - "Star Collector" — 100+ total stars across repos

### 5.6 AI-Generated Portfolio Summary
- A short (3–5 sentence) natural-language summary generated by an LLM, describing the developer's apparent focus areas, strengths, and activity level based on aggregated data (not raw code).
- Regeneratable on demand.
- Clear labeling that the summary is AI-generated.

## 6. User Stories

1. *As a visitor*, I want to type a GitHub username and see their stats immediately, so I don't have to browse GitHub manually.
2. *As a developer*, I want to see my most-used languages visualized, so I can confirm my resume reflects my actual work.
3. *As a recruiter*, I want a one-paragraph AI summary of a candidate's profile, so I can quickly gauge fit before a deeper review.
4. *As a returning user*, I want my recent searches saved, so I can quickly revisit profiles I've already looked up.
5. *As any user*, I want clear loading and error states, so I understand what's happening if a username is invalid or GitHub's API is slow.

## 7. Success Metrics (for a resume project, these are demonstration targets, not live KPIs)

- Dashboard fully loads for a valid username in < 3 seconds (with caching).
- Handles GitHub API rate limits gracefully (no unhandled failures).
- Works for accounts with 0 repos and accounts with 500+ repos without breaking layout.
- AI summary generation succeeds > 95% of the time given valid input data.

## 8. Out of Scope (v1)

- Private repository data (requires OAuth scopes beyond public read).
- Organization-level dashboards (only individual user accounts).
- Historical trend comparison across multiple time periods.
- Editing/customizing the dashboard (e.g., theming, pinning repos) — future consideration.
- Mobile native app (web-responsive only).

## 9. Assumptions & Constraints

- Relies on GitHub's public REST/GraphQL APIs; subject to their rate limits (60 req/hr unauthenticated, 5,000 req/hr authenticated).
- AI summary depends on a third-party LLM API and incurs per-call cost — usage should be cached/limited.
- Contribution graph data is only available via GitHub's GraphQL API and requires authenticated requests.
- This is a solo/portfolio project — scope is intentionally sized to be buildable in a reasonable timeframe while still demonstrating production-relevant skills.

## 10. Risks

| Risk | Mitigation |
|---|---|
| GitHub API rate limiting blocks demo usage | Use authenticated requests + server-side caching |
| AI API costs scale with traffic | Cache AI summaries per user for a TTL (e.g., 24h) |
| Large accounts (many repos) slow down response | Paginate/limit repos fetched, parallelize requests |
| GitHub API schema changes | Isolate API calls behind a service layer (see TRD) |

## 11. Milestones (suggested)

1. Project setup, GitHub OAuth/token auth working
2. Core data fetching (profile, repos, languages)
3. Contribution heatmap + streaks
4. Charts (languages, repo insights)
5. AI summary integration
6. Polish: loading/error states, responsive design
7. Deploy + write README/case study for resume
